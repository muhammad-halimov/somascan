# <img src="docs/favicon.ico" alt="Somaco" height="40" align="middle"> Somasync

Программа для компьютера (Windows и macOS) для **Somaco (Holcim), Румыния** — учёт арматурной стали по плавкам: распределение расхода элементов из месячного отчёта Consum по плавкам, блоки элементов в Sarjele и отметка израсходованных плавок в Probe.

**Интерфейс:** <img src="docs/flags/gb.svg" height="14" alt=""> English · <img src="docs/flags/ro.svg" height="14" alt=""> Română · <img src="docs/flags/tj.svg" height="14" alt=""> Тоҷикӣ · <img src="docs/flags/ru.svg" height="14" alt=""> Русский  
**Стек:** Electron 44 · React 19 · TypeScript · Vite 8 · ExcelJS · i18next

## Как это работает

```mermaid
flowchart LR
  consum@{ shape: doc, label: "Consum<br/>расход за месяц" } --> engine["Движок"]
  delivered@{ shape: doc, label: "Probe otel<br/>поступившие плавки" } --> engine
  phones@{ shape: doc, label: "Копия Probe в Google Drive<br/>бирки с телефонов" } --> engine
  engine --> sarjele@{ shape: doc, label: "Sarjele<br/>блоки элементов по плавкам" }
  engine --> used@{ shape: doc, label: "Probe otel<br/>израсходованные плавки, бирки" }
  engine --> ids@{ shape: doc, label: "Consum<br/>ID элементов" }
```

| Файл | Содержание |
|---|---|
| **Consum** (лист «Decont Lunar») | расход за месяц: проекты, элементы, кг стали по кодам материала |
| **Sarjele din elemente** | лист на проект, блок на элемент: плавки и кг |
| **Probe otel** | журнал поставок; израсходованная плавка закрашивается жёлтым |

Порядок прогона:

1. **Слежение.** Сохранение Consum (изменение времени и размера) запускает движок.
2. **Чтение.** Движок читает поставки из Probe, списания из Sarjele и расход из Consum.
3. **Связи.** Каждому элементу сопоставляется блок Sarjele: по ID (`NI-0004`), реестру, ручной привязке или похожему названию; иначе создаётся новый блок.
4. **План.** Остаток плавки = поступило минус списано; расход распределяется по плавкам соответствующего Ø и формы.
5. **Запись:** копия, Sarjele, Probe, ID в Consum, проверка.

Каждый прогон отображается на главной вкладке карточкой с итогом: «Записано», «Только план», «Без изменений», «Отложено», «Ошибка». Настройки, `log.txt` и `links.json` хранятся в `%APPDATA%\Somasync\` (Windows) или `~/Library/Application Support/Somasync/` (macOS).

**Безопасность данных:** пробный режим без записи; копия перед каждой записью и откат на вкладке «Расширенные»; запись через временный файл с проверкой; файл, открытый в редакторе, не записывается — запись откладывается до его закрытия. Вся обработка выполняется локально; файлы передаются только в Google Drive и только если он выбран хранилищем.

## Рабочие места

Вкладки вверху главной (выбранная запоминается): **Atelier**, **Laborator**, **Calitate**.

| | Atelier | Laborator | Calitate |
|---|---|---|---|
| Таблицы | Consum, Sarjele, Probe | Laborator.xlsx (таблица коэффициентов) | Calitate.xlsx (пока без обработки) |
| Хранилище | этот компьютер, сетевой диск, Google Drive, «Устройства» | этот компьютер, сетевой диск | этот компьютер, сетевой диск |
| «Связи», правила, ручные привязки | есть | нет | нет |
| Подпись («Расширенные») | мастера | лаборанта | контролёра |
| Слежение («Старт») | Consum → Sarjele и Probe | чтение последней записи Laborator.xlsx | пока нет |
| Миграция | ID блоков Sarjele | Nr.bul. и Data — в свои колонки | нет |
| Проверка таблицы в «Хранилище» | листы: Decont Lunar, лист года, листы проектов | шапка: Rc decofr., Nr.bul., Data (таблица разделена) | файл есть и читается |

У Laborator и Calitate своё место хранения и своя таблица; учётная запись и расположение сетевого диска — общие. Во время слежения рабочее место не меняется. Режим «Записывать в файлы» есть только у Atelier: Laborator таблицу только читает.

**Слежение Laborator** (`engine/laborator/LaboratorReader.ts`): при «Старте» и каждом изменении `Laborator.xlsx` таблица копируется в `backup/Laborator` (всегда, хотя и не меняется), затем в журнал попадает последняя запись — нижняя строка под шапкой с заполненными «Rc decofr.», «Nr.bul.» или «Data» (заготовленные ниже строки без результатов пропускаются) — и подпись лаборанта. Таблица в прежнем виде (не разделена миграцией) — ошибка с подсказкой. Разово — «Расширенные → Прочитать таблицу».

**Подписи** («Расширенные» каждого рабочего места — мастер, лаборант, контролёр; `host/SignatureService.ts`): PNG с прозрачным фоном; изображение без прозрачности не принимается. Прозрачные поля вокруг подписи обрезаются, слишком большое изображение уменьшается, копия хранится в папке данных программы (`signatures/`). Превью — на белом листе в клетку в любой теме. Подпись лаборанта передаётся движку при чтении таблицы (`SIGNATURE`).

**Миграция Laborator** (`engine/laborator/`, «Расширенные → Демонстрационная / Фактическая миграция»): номер бюллетеня и дата из ячеек «Rc decofr.» (`32.8↵1B/09.01.2026`) и «Nr.bul./Data» справа от «Rc 28 zile» (`1B/05.02.2026`) переносятся в новые колонки «Nr.bul.» и «Data»; прочность — числом, дата — датой Excel (`dd.mm.yyyy`). Объединения, ширины, фильтр и область печати сдвигаются вместе с колонками. Ячейки с опечатками («37..5», «18.08.02026») остаются как были и перечислены в «Требуют внимания». Новая книга проверяется до записи; оригинал остаётся рядом как `Laborator Orig.xlsx` (если такой файл уже есть, миграция не выполняется), копия — в `backup/Laborator`. Разделённая таблица повторно не меняется.

## Хранение таблиц

Таблицы должны существовать заранее; программа их не создаёт. У каждого хранилища свой набор файлов.

- **Этот компьютер** — пути к таблицам.
- **Сетевой диск** (SMB, `host/SmbShare.ts`) — учётная запись (домен, пользователь, пароль) и расположение (сервер, общая папка). «Проверить подключение» подключает папку системными средствами: Windows — `net use \\server\share` (пути `\\server\share\…`), macOS — `mount volume smb://…` (папка появляется в `/Volumes`, точка подключения берётся из `mount`); затем таблицы выбираются значком папки. Пароль хранится в зашифрованном виде (DPAPI / Keychain).
  - Обязательны сервер и, без «Без авторизации», пользователь и пароль; общая папка — нет: без неё берётся папка из путей таблиц, а если путей ещё нет — Windows входит на сервер (`\\server\IPC$`), macOS предлагает выбрать папку своим окном.
  - Пока диск не подключён, таблицы на нём недоступны (пути, выбор файла, проверка); состояние проверяется при открытии вкладки и после правки сервера или папки.
  - Перед подключением проверяется, отвечает ли сервер (TCP 445/139 или порт из `сервер:порт`). Ошибки — понятным текстом по номеру ошибки системы (Windows и macOS, например «Сервер отклонил подключение — проверьте адрес, порт и общую папку» вместо «-5014»); неизвестный номер — общая фраза с номером.
  - Таблицы читаются средствами системы, как обычные файлы. Если у Windows уже есть доступ к папке (вход в домен, сохранённые учётные данные, открытый доступ), учётная запись в программе не нужна.
  - «Без авторизации» — подключение без имени и пароля, под текущей учётной записью системы.
  - Перед началом слежения программа сама подключает папку, если таблицы на ней недоступны (например, после перезапуска системы).
- **Google Drive** — вход через аккаунт Google в системном браузере (OAuth для программ на компьютере: ответ возвращается на `http://127.0.0.1:<порт>`, PKCE; страница итога — по-английски, через 5 с закрывается, а окно Somasync выходит на передний план), ссылка на папку и имена таблиц. Без OAuth-клиента «Войти через Google» сообщает, что Google Drive не настроен. Таблицы обрабатываются в локальной копии (`<данные программы>/drive/<id папки>/`): скачиваются только изменённые, используются те же блокировки `<таблица>.lock`, что и в мобильном приложении, прежняя версия сохраняется в `backups` на сервере. Таблица, изменённая в Drive во время прогона, не перезаписывается.

Настройка Google Cloud (однократно; проект и экран согласия — те же, что у мобильного приложения, см. его [руководство по сборке](https://github.com/muhammad-halimov/somascan/blob/main/guides/BUILD.ru.md#google-drive-oauth-клиенты)):

1. [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Library → **Google Drive API** → Enable.
2. Google Auth Platform → Data access → доступ `https://www.googleapis.com/auth/drive`; Audience → Test users для экрана External в режиме «Testing».
3. Google Auth Platform → Clients → Create client → тип **Desktop app** → Create → Download JSON.
4. JSON помещается в корень проекта как `google-oauth.json` (в репозиторий не входит) — сборка встраивает клиент в программу. Другие способы: переменные `SOMASYNC_GOOGLE_CLIENT_ID=… SOMASYNC_GOOGLE_CLIENT_SECRET=… npm run dist:win` (имеют приоритет) или `google-oauth.json` в папке данных уже собранной программы.

## Устройства

Если таблицы находятся на этом компьютере или сетевом диске, а у телефонов нет доступа к сети компании, мобильное приложение записывает бирки в **копию Probe в Google Drive**, а Somasync переносит их в Probe («Хранилище → Устройства»; код — `host/PhoneBridge.ts`, `engine/ProbeBridge.ts`).

- «Бирки с Google Drive» включены по умолчанию; переключатель, папка и имя копии закрыты замками от случайной правки.
- Копия проверяется раз в 15 с во время слежения с записью (по MD5).
- Новые бирки (по скрытому листу `somascan-journal`) дописываются в Probe той же строкой, что записал бы телефон; затем Probe заменяет копию.
- Пока Probe открыт в Excel, перенос откладывается, копия не заменяется.
- Бирка с плавкой, которая уже есть в Probe, пропускается с указанием причины в журнале.

**Firebase Firestore** (необязательно, под замком) — мгновенный перенос: после записи телефон обновляет документ `somascan-bells/<канал>` (канал — SHA-256 от «id папки/имя копии», одинаковый на телефоне и в программе без отдельной настройки), и программа сразу запускает проверку. Firestore хранит только время последнего уведомления. Проверка копии остаётся запасной.

Настройка (однократно; подробно — в [руководстве по сборке мобильного приложения](https://github.com/muhammad-halimov/somascan/blob/main/guides/BUILD.ru.md#firebase-firestore)):

1. [Консоль Firebase](https://console.firebase.google.com/) → добавить Firebase в проект Google Cloud или создать новый.
2. Firestore Database → создать базу (Standard) → Rules: правила ниже → Publish.
3. Project settings → General: ID проекта и Web API key (если ключа нет — Add app → Web). Web API key не является секретом: доступ задают правила.
4. ID и ключ вводятся на компьютере («Хранилище → Устройства → Уведомления Firebase Firestore») и на телефонах («Настройки → Хранилище → Google Drive → Firebase Firestore»).

Бесплатной квоты (50 000 чтений и 20 000 записей в день) достаточно с запасом.

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /somascan-bells/{channel} {
      allow get: if channel.size() == 64;
      allow create, update: if channel.size() == 64 && request.resource.data.keys().hasOnly(['at']);
    }
  }
}
```

## Правила работы

- **Режимы.** Пробный режим ничего не записывает; запись включается «Записывать в файлы» на главной или «Фактический прогон» в «Расширенных». «Старт» включает слежение.
- **Миграция** (однократно, для Sarjele, который вели вручную): существующие блоки получают ID без распределения по плавкам. Порядок: демонстрационная миграция → «Требуют внимания» на вкладке «Связи» → фактическая миграция.
- **Consum.** Лист `Decont Lunar`; колонки определяются по шапке (ELEMENT, «ID sync»); расход — колонки AK…AZ (код в строке 9, Ø в строке 7, форма в строке 8: «bob» — Bobina, иначе Bara); данные с 10-й строки. Для формул берётся сохранённый результат.
- **Новый месяц.** Месяц берётся из `LUNA <МЕСЯЦ> <ГОД>`; новый Consum — копия прошлого, ID переходят к нему.
- **Проекты.** Проект обрабатывается только при привязке к листу Sarjele (вкладка «Связи») или с «Новые проекты подключать сами».
- **Плавки.** «С последней использованной» начинает с плавки, записанной последней. Нехватка стали отображается как «— НЕТ ОСТАТКА —» и не записывается. Жёлтый снимается только с плавок, закрашенных программой (скрытый лист `sync-journal`).
- **Служебные данные.** Колонка «ID sync» в Consum и колонка «Model ID» в Sarjele скрыты; все ID — на скрытом листе `sync-registry` в Sarjele.
- **Копии** сохраняются рядом с таблицами в `backup/`, у каждого рабочего места — своя папка: `backup/Atelier/Consum`, `backup/Atelier/Probe`, `backup/Atelier/Sarjele`, `backup/Laborator`, `backup/Calitate`. Откат — «Расширенные → Откат из копии», для таблиц выбранного рабочего места. Копии прежних версий (`backups/`) остаются в списке отката.

## Ручные привязки: links.json

Задаёт блок для элемента Consum, когда автоматическая привязка невозможна или неверна. Выпадающий список на вкладке «Связи» пишет в этот же файл; открывается он через «Расширенные → Ручные привязки (links.json)».

```json
{
  "PETRA DATE|ST_100": "ST_100.110",
  "PETRA DATE|ST_110": "@new",
  "NORD INFRA|GRINDA 7": "@skip"
}
```

| Значение | Действие |
|---|---|
| `"название блока"` | запись в этот блок (пока у элемента нет ID) |
| `"@new"` | создание нового блока (пока у элемента нет ID) |
| `"@skip"` | элемент не обрабатывается |

Ключ — `ПРОЕКТ|элемент`; регистр и лишние пробелы не учитываются. Порядок поиска: `@skip` → ID в Consum → реестр в Sarjele → links.json → похожее название → новый блок. Неверный JSON останавливает прогоны с ошибкой; программа файл не перезаписывает.

## Разработка

```bash
npm install
npm start          # сборка и запуск из папки проекта
```

| Команда | Назначение |
|---|---|
| `npm run build` | `tsc -b` + окно (`dist/`) + движок (`dist-engine/`) + главный процесс (`dist-host/`) |
| `npm test` | все проверки (`node:test` + `tsx`) |
| `npm run dist` / `dist:x64` | macOS (Apple Silicon / Intel) → `release/` |
| `npm run dist:win` | Windows x64 → `release/Somasync-<версия>-win-x64.zip` |

- **Windows:** архив распаковывается в любую папку, программа запускается через `Somasync\Somasync.exe`; установка не требуется.
- **macOS:** после распаковки Somasync закрывается (Cmd+Q) и запускается `install-macos.command` рядом с `Somasync.app` (в первый раз: правый клик → «Открыть»); он копирует программу в «Программы», снимает карантин и подписывает её локально — постоянным ключом «Somasync Local Signing» (создаётся один раз в связке ключей входа). С ним доступ программы к паролю сетевого диска и входу Google в связке ключей разрешается один раз («Разрешить всегда»), а не после каждой установки; не расшифровались — сообщение в журнале, пароль вводится снова. Изменения проекта попадают в установленную программу только так.

Проверки выполняются на синтетических книгах (`tests/fixtures.ts`) и пустом журнале мобильного приложения (`tests/fixtures/Probe otel.xlsx`); Google Drive проверяется на поддельном сервере, вход — через `127.0.0.1` с поддельным сервером токенов (`tests/drive.test.ts`), мост с телефонами — с настоящим движком (`tests/phoneBridge.test.ts`, `tests/bridge.test.ts`). Реальные файлы завода в проект не входят: перед выпуском новой версии движка старая и новая версии запускаются на копиях реальных файлов, журнал и результат сравниваются.

## Структура

```
src/
  app/                  окно: вкладки, тема, состояние, слушатель Firestore
  features/             вкладки: run (главная), storage, links, settings («Расширенные»)
  locales/              тексты en / ro / tj / ru
  shared/               общее для окна, главного процесса и движка
  host/                 главный процесс Electron: настройки, журнал, слежение, сетевой диск, Google Drive, телефоны, подпись
  engine/               движок без Electron и React: планирование, книги, запись, lab (бирки), laborator (таблица лаборатории)
tests/                  проверки
```

Соглашения: движок взаимодействует только через аргументы, код выхода (0 — готово, 1 — ошибка, 3 — отложено) и JSON-файл; тексты передаются кодами сообщений и переводятся окном; импорты через `@/`; комментарии на русском; рискованные места отмечены `РИСК:`.

## Известные риски

| Что | Последствие |
|---|---|
| Блоки Sarjele и колонки Probe определяются по тексту шапки | переименованная шапка исключает блок или лист |
| Форма в Consum определяется по «bob» в строке 8 | опечатка меняет форму |
| ID в Consum записываются правкой XML | в нестандартном файле ID могут не записаться (с предупреждением) |
| Файл-замок аварийно закрытого редактора | запись откладывается до удаления замка |
| Пауза после изменения Consum | на медленной сети может быть прочитан недописанный файл |
| Пароль и ключ Google без системного шифрования | хранятся в `state.json` в base64 (`raw:`) |
| Колонки таблицы Laborator определяются по тексту шапки («decofr», «28 zile», «Nr.bul», «Data») | переименованная шапка — миграция и чтение не выполняются (с причиной) |
| Последняя запись Laborator — нижняя заполненная строка | запись, вставленная выше последней, не считается последней |
| Копия Laborator при каждом изменении | папка `backup/Laborator` растёт в пределах срока хранения копий |
| Проверка сервера сетевого диска (TCP) | в macOS 15+ программа может спросить доступ к «Локальной сети»; без него проверка пропускается |
| Запись бирки повторяет логику мобильного приложения (`engine/lab/`) | изменения вносятся вместе с `features/uploads/xlsx/` в main |
