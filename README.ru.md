# <img src="docs/favicon.ico" alt="Somaco" height="40" align="middle"> Somasync

Программа для компьютера (Windows и macOS) для **Somaco (Holcim), Румыния**: учёт арматурной стали по плавкам.

Программа следит за месячным отчётом Consum. Когда оператор его сохраняет, она раскладывает расход каждого элемента по плавкам, пишет блоки элементов в Sarjele и закрашивает жёлтым израсходованные плавки в Probe — работу, которую раньше делали вручную. Ещё она переносит в Probe бирки, которые телефоны без сети компании пишут в копию Probe в Google Drive.

**Интерфейс:** <img src="docs/flags/gb.svg" height="14" alt=""> English · <img src="docs/flags/ro.svg" height="14" alt=""> Română · <img src="docs/flags/tj.svg" height="14" alt=""> Тоҷикӣ · <img src="docs/flags/ru.svg" height="14" alt=""> Русский  
**Стек:** Electron 44 · React 19 · TypeScript · Vite 8 · ExcelJS · i18next

## Как это работает

```
Consum (Decont Lunar) ──► движок ──► Sarjele (блоки элементов, реестр ID)
        ▲                        └─► Probe (жёлтые плавки, sync-journal)
        └── ID элементов (скрытая колонка «ID sync»)
хранилище: этот компьютер | сетевой диск | Google Drive
```

### Файлы

Арматурная сталь идёт в элементы (балки, стены, колонны) строительных проектов. Она приходит плавками: у каждой свой номер, диаметр (Ø), форма — пруток (Bara) или бухта (Bobina) — и вес.

| Файл | Что в нём |
|---|---|
| **Consum** (лист «Decont Lunar») | расход за месяц: проекты, элементы и кг стали по кодам материала; заполняют операторы |
| **Sarjele din elemente** | лист на проект, блок на элемент: из каких плавок и сколько кг он сделан |
| **Probe otel** | журнал поставок: какие плавки пришли и сколько; израсходованная плавка закрашивается жёлтым |

Чтобы узнавать элемент из месяца в месяц, программа ставит ему ID (`NI-0004`) — в скрытой колонке Consum и рядом с блоком в Sarjele.

### Прогон

1. **Слежение.** Раз в несколько секунд программа сравнивает время изменения и размер Consum; после изменения ждёт паузу и запускает движок.
2. **Чтение.** Движок (отдельный процесс) читает Probe (сколько пришло по плавке), Sarjele (сколько уже списано) и Consum (элементы, расход, ID, месяц).
3. **Связи.** Элемент Consum ищет свой блок Sarjele: по ID, по реестру, по ручной привязке, по похожему названию. Не нашёл — новый блок с новым ID.
4. **План.** Остаток плавки = пришло по Probe минус списано в Sarjele; считается заново при каждом прогоне. Расход раскладывается по плавкам нужного Ø и формы.
5. **Запись:** копия, Sarjele, Probe, ID в Consum, затем проверка.

### Журнал

На главной события программы — одной строкой, каждый прогон движка — карточкой: что его запустило, режим и итог — «Записано», «Только план», «Без изменений», «Отложено», «Ошибка». Внутри — блоки Sarjele, ID элементов, закрашенные или снятые плавки в Probe, нехватка стали, элементы, требующие внимания, и проверка после записи. «Подробно» — технический вывод движка на языке интерфейса; тот же текст пишется в `log.txt`.

Настройки, `log.txt` и `links.json` лежат в папке данных программы: `%APPDATA%\Somasync\` на Windows, `~/Library/Application Support/Somasync/` на Mac.

### Безопасность данных

- **Пробный режим** ничего не пишет.
- **Копия** перед каждой записью; откат — на вкладке «Расширенные».
- **Открытые файлы.** Если Sarjele или Probe открыт в редакторе, запись откладывается и повторяется, когда файл закроют (иначе сохранение из редактора её затрёт). Если открыт только Consum, ждут ID. Отключается в «Расширенные → Не писать в открытые файлы».
- **Запись** идёт через временный файл и проверяется после.
- **Локально.** Всё работает на этом компьютере; файлы никуда не уходят, кроме вашего Google Drive, и только когда он выбран хранилищем (Sarjele — конфиденциальный файл).

## Хранение таблиц

Таблицы должны уже существовать — программа их не создаёт. У каждого хранилища свой набор файлов; смена хранилища на вкладке «Хранилище» меняет и набор. Каждое поле таблицы закрыто замком от случайной правки; значок проверки в его конце показывает, есть ли файл и какие в нём листы. Лист Probe по умолчанию — текущего года; пока он пуст, читается и прошлый год.

### Этот компьютер и сетевой диск

- **Этот компьютер** — пути к таблицам, выбираются значком папки.
- **Сетевой диск** (общая папка SMB) — учётная запись (домен, пользователь, пароль) и расположение (сервер, общая папка). «Проверить подключение» подключает папку системными средствами: `net use \\server\share` на Windows, `mount volume smb://…` на macOS. Пароль хранится зашифрованным (DPAPI / Keychain).

### Google Drive

Движок работает с файлами, поэтому таблицы Drive лежат в локальной копии (`<данные программы>/drive/<id папки>/`). Код — в `host/drive/`.

- **Вход** открывает страницу Google в системном браузере (OAuth для программ на компьютере, PKCE). Ключ доступа хранится зашифрованным и не попадает в окно.
- **Папка и таблицы** — ссылка на папку или её ID и имена таблиц в ней.
- **Скачивание** — перед каждым прогоном, только изменившиеся таблицы (по версии Drive и MD5).
- **Блокировка** — те же файлы `<таблица>.lock`, что у мобильного приложения: телефон и компьютер не затирают Probe друг другу.
- **Выгрузка** — после прогона с записью: прежняя версия уходит в `backups` на сервере, новая проверяется по MD5. Таблицу, изменённую в Drive во время прогона, программа не перезаписывает — следующий прогон пересчитает.

**Настройка Google Cloud (один раз):**

1. В [Google Cloud Console](https://console.cloud.google.com/) включить **Google Drive API** (подойдёт проект мобильного приложения).
2. Создать OAuth-клиент типа **Desktop app**. Доступ — `https://www.googleapis.com/auth/drive`.
3. Положить JSON клиента в папку данных программы как `google-oauth.json` или собрать с ним: `SOMASYNC_GOOGLE_CLIENT_ID=… SOMASYNC_GOOGLE_CLIENT_SECRET=… npm run dist:win`.
4. Пока экран согласия в режиме «Testing», добавить аккаунты склада в Test users.

### Телефоны

Если таблицы на этом компьютере или сетевом диске, а телефоны не достают до сети компании, мобильное приложение пишет бирки в **копию Probe в Google Drive**, а Somasync переносит их в Probe. Включается в «Хранилище → Телефоны»; аккаунт и папка — те же, что у хранилища Google Drive. На телефонах — хранилище Google Drive с той же папкой и тем же именем. Код — `host/PhoneBridge.ts` и команда движка `--bridge` (`engine/ProbeBridge.ts`).

- **Когда.** Во время слежения с записью, не чаще раза в 15 с: программа сверяет MD5 копии.
- **Копию изменили.** Под блокировкой телефонов `Probe otel.xlsx.lock` копия скачивается, и бирки, которых ещё нет в Probe (по скрытому листу `somascan-journal`), дописываются той же строкой, что записал бы телефон (`engine/lab/` повторяет мобильное приложение). Затем Probe выкладывается на место копии. В журнале — карточка «Бирки с телефонов».
- **Изменился только Probe** — Probe выкладывается на место копии. Копии нет — она создаётся.
- **Не перенесено:** плавка уже есть в Probe, нет листа, запись без бирки — пропуск с причиной в карточке.
- **Probe открыт в Excel** — перенос ждёт («Перенос отложен: Probe открыт»), копия не заменяется.
- **Безопасность:** копия Probe, проверка новой книги до записи, прежняя копия в Drive уходит в `backups`. Сверенное состояние хранится в `bridge.json`.

**Firebase Firestore (необязательно, под замком).** После записи телефон обновляет документ `somascan-bells/<канал>` (SHA-256 от «id папки/имя копии»); окно слушает его (`app/bellListener.ts`) и сразу запускает проверку. Firestore хранит только время последнего звонка. Проверка копии остаётся запасной. Под переключателем — «Firestore: подключено» или ошибка.

Настройка (один раз):

1. В [консоли Firebase](https://console.firebase.google.com/) добавить Firebase в проект Google Cloud или создать новый.
2. Firestore Database → создать базу (Standard), задать правила ниже.
3. «Project settings» → ID проекта и Web API key (ключа нет — добавить веб-приложение). Ключ не секрет: доступ задают правила.
4. Ввести ID и ключ здесь и на телефонах («Настройки → Хранилище → Google Drive → Firebase Firestore»).

Бесплатной квоты (50 000 чтений и 20 000 записей в день) хватает с запасом.

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /somascan-bells/{channel} {
      allow get: if channel.size() == 64;
      allow create, update: if channel.size() == 64 && request.resource.data.keys().hasOnly(['at']);
    }
  }
}
```

## На практике

### Запуск и прогоны

- Пробный режим ничего не пишет. Чтобы писать: «Записывать в файлы» на главной или «Фактический прогон» в «Расширенных».
- «Старт» включает слежение; оно продолжается после перезапуска.
- **Прогон** («Расширенные → Действия») — один полный проход по Consum по кнопке. «Демонстрационный прогон» показывает план, «Фактический прогон» записывает (с копией).
- **Миграция** — однократный перевод старого Sarjele, который вели вручную, под управление программы: существующие блоки получают ID (рядом с блоком, в `sync-registry` и в «ID sync» Consum); по плавкам ничего не раскладывается. Порядок: демонстрационная миграция → разобрать «Требуют внимания» на вкладке «Связи» → фактическая миграция → обычная работа.

### Слежение

- Прогон запускает только сохранение Consum; правки в Sarjele или Probe — нет.
- На медленном сетевом диске стоит увеличить паузу после изменения.
- Пропавший файл в журнале — «недоступен», вернувшийся — «снова доступен».
- Своя запись ID в Consum не запускает ещё один прогон.
- Аварийно закрытый редактор может оставить файл-замок (`~$…` или `.~lock.…#`) и откладывать запись; путь к нему — в журнале.

### Consum

- Лист `Decont Lunar`. Колонки ищутся по шапке: ELEMENT (строки 7–9), «ID sync» (строки 1–9).
- Расход — колонки AK…AZ: код в строке 9, Ø в строке 7, форма в строке 8 («bob» — Bobina, иначе Bara).
- Проекты — объединённые ячейки колонки A; проект со всеми скрытыми строками не используется.
- Строки с 10-й; «TOTAL…» и «PIERDERI…» пропускаются; килограммы округляются.
- Для формул берётся сохранённый результат: файл, сохранённый без пересчёта, даёт пустой расход.
- В колонке ID — только вид `NI-0004`; чужой текст или повтор ID пропускает строку.
- **Новый месяц.** Месяц берётся из `LUNA <МЕСЯЦ> <ГОД>`. Новый Consum — копия прошлого; ID переходят к нему, если старый файл убран из «Хранилища» или месяц нового позже.

### Связи

- Проекты — таблица «проект Consum → лист Sarjele». Лист закрыт замком; чтобы выбрать вручную, откройте замок.
- Ненастроенный проект не обрабатывается. С «Новые проекты подключать сами» он подключается и получает лист сам.
- Несколько похожих блоков или один блок на несколько строк — элемент пропускается; блок выбирается в «Элементы и блоки».
- Ручные привязки — `links.json`, см. [ниже](#ручные-привязки-linksjson).

### Плавки

- «С последней использованной» начинает с плавки, которой писали последней; более старые незакрытые плавки перечисляются в журнале.
- Не хватает стали — в плане строка «— НЕТ ОСТАТКА —», в Sarjele она не пишется.
- Под блоком нет свободных строк — элемент пропускается.
- Жёлтый снимается только с плавок, которые закрасила сама программа (скрытый лист `sync-journal` в Probe).

### Запись и служебные данные

- Перед записью все файлы копируются в `backups/` рядом с ними. Откат: «Расширенные → Откат из копии».
- Оставшаяся после сбоя папка `<файл>.lock` снимается сама.
- В Consum меняется только скрытая колонка «ID sync»; формулы и оформление не трогаются. Её буква — в «Подробно».
- В Sarjele колонка «Model ID» (коды и ID блока) скрыта, а если она общая с другими блоками — текст в ней невидим (`;;;`).
- Все ID — на скрытом листе `sync-registry` в Sarjele.

## Ручные привязки: links.json

Файл говорит программе, какой блок Sarjele взять для элемента Consum, когда она не может решить сама или решает не так. Выпадающий список у элемента на вкладке «Связи» пишет в этот же файл. Открыть — «Расширенные → Ручные привязки (links.json)»; на каждом компьютере свой.

```json
{
  "PETRA DATE|ST_100": "ST_100.110",
  "PETRA DATE|ST_110": "@new",
  "NORD INFRA|GRINDA 7": "@skip"
}
```

Ключ — `ПРОЕКТ|элемент`: название проекта в программе и название из колонки ELEMENT; регистр и лишние пробелы не важны.

| Значение | Что делает | Действует |
|---|---|---|
| `"название блока"` | писать в этот блок (без ID) | пока у элемента нет ID |
| `"@new"` | создать новый блок | пока у элемента нет ID |
| `"@skip"` | никогда не обрабатывать элемент | всегда |

**Порядок поиска:** `@skip` → ID в Consum → реестр в Sarjele → links.json → старый блок с похожим названием → новый блок.

**Ошибки:**

- Неверный JSON останавливает прогоны карточкой «Ошибка» (причина и место); сломанный файл программа не перезаписывает.
- Неизвестный блок или команда — элемент пропускается в «Требуют внимания».
- Ключ без `|` или значение не текстом — строка пропускается с предупреждением.
- Один элемент дважды — действует последняя строка; один блок — один элемент.
- BOM и пустой файл принимаются.

## Разработка

```bash
npm install
npm start          # сборка и запуск из папки проекта
```

| Команда | Что делает |
|---|---|
| `npm start` | сборка и запуск |
| `npm run build` | проверка типов, окно (`dist/`), движок (`dist-engine/`), главный процесс (`dist-host/`) |
| `npm test` | все проверки (`node:test` + `tsx`) |
| `npm run dist` | macOS (Apple Silicon) → `release/` |
| `npm run dist:x64` | macOS (Intel) |
| `npm run dist:win` | Windows x64 → `release/Somasync-<версия>-win-x64.zip` |

**Тесты** идут на маленьких синтетических книгах и пустом журнале мобильного приложения `tests/fixtures/Probe otel.xlsx`: план, запись, повторный прогон, открытый файл, откат, блокировки, копии, плавки, настройки, links.json, переводы, Google Drive на поддельном сервере и мост с телефонами с настоящим движком. Настоящих файлов завода в проекте нет; перед выпуском нового движка сравните старую и новую версии на их копиях.

## Сборка

- **Windows:** распаковать в любую папку и запустить `Somasync\Somasync.exe`; установка не нужна. Собрать можно и на Linux или macOS.
- **macOS:** распаковать, закрыть Somasync (Cmd+Q) и запустить `install-macos.command` рядом с `Somasync.app` (в первый раз: правый клик → «Открыть»). Он копирует программу в «Программы», снимает карантин и подписывает её локально.

### Соглашения

- Движок общается с программой только через аргументы, переменные окружения, код выхода (0 — готово, 1 — ошибка, 3 — отложено) и JSON-файл (`JSON_OUT`).
- Тексты движка и главного процесса — коды сообщений; переводит их окно. Новый текст — ключ во всех четырёх `locales/<язык>/`; тесты сверяют ключи и параметры.
- Окно говорит с главным процессом только через `window.api`.
- Импорты через `@/`; комментарии на русском; риски отмечены `РИСК:`.
- Без базы данных: данные живут в самих файлах, поэтому ручные правки учитываются и источник правды один.

## Известные риски

| Что | Где | Последствие |
|---|---|---|
| Блок Sarjele узнаётся по шапке (Model / ø / KG) | `engine/books/SarjeleBook.ts` | переименованная шапка теряет блок и его расход |
| Колонки Probe ищутся по словам шапки | `engine/books/ProbeBook.ts` | переименованная шапка выключает лист |
| Форма в Consum — по «bob» в строке 8 | `engine/books/ConsumBook.ts` | опечатка меняет форму |
| ID в Consum пишутся правкой XML | `engine/books/ConsumIdPatcher.ts` | в необычном файле ID могут не встать (с предупреждением) |
| Вид таблицы вокруг скрытой колонки «Model ID» | `engine/books/SarjeleWriter.ts` | после смены оформления проверить настоящий Sarjele на глаз |
| Пустой скрытый лист считается листом нового проекта | `engine/books/SarjeleWriter.ts` | такой лист переименуется и покажется |
| Файл-замок аварийно закрытого редактора | `engine/FileGuard.ts` | запись ждёт, пока замок не удалят |
| Возраст брошенной блокировки — по часам | `engine/FileGuard.ts` | при расхождении часов больше 10 минут возможна ошибка |
| Пауза после изменения Consum | `host/ConsumWatcher.ts` | на медленной сети может прочитаться недописанный файл |
| Пароль сетевого диска и ключ Google, когда системное шифрование недоступно | `host/SettingsStore.ts` | хранятся в `state.json` в base64 (`raw:`), их прочтёт любой с доступом к файлу |
| Таблица Drive изменилась во время прогона | `host/drive/DriveMirror.ts` | не выкладывается; следующий прогон пересчитает |
| Probe открыт в Excel весь день | `host/PhoneBridge.ts` | бирки с телефонов ждут в копии |
| Лист года бирки — по часам телефона | `engine/lab/LabelWorkbook.ts` | неверная дата — не тот лист |
| Запись бирки повторяет мобильное приложение | `engine/lab/` | менять вместе с `features/uploads/xlsx/` в main |
