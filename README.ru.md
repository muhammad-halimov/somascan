# <img src="src/assets/favicon.ico" alt="Somaco" height="40" align="middle"> Somascan

Мобильное приложение для **Somaco (Holcim), Румыния**: читает бирки поступающей арматуры и записывает их в журнал проб стали `Probe otel.xlsx` на сетевом диске Windows или в Google Drive.

**Интерфейс:** <img src="docs/flags/gb.svg" height="14" alt=""> English · <img src="docs/flags/ro.svg" height="14" alt=""> Română · <img src="docs/flags/tj.svg" height="14" alt=""> Тоҷикӣ · <img src="docs/flags/ru.svg" height="14" alt=""> Русский  
**Стек:** Vite · React 19 · TypeScript · Capacitor 8 (Android / iOS) · oxlint

## Как это работает

```mermaid
flowchart LR
  photo["Фото бирки"] --> device["На устройстве<br/>ML Kit / Vision + правила полей"]
  photo --> model["ИИ-модель<br/>Gemini · Claude · OpenAI · LM Studio"]
  device --> fields["Поля<br/>проверка и правка"]
  model --> fields
  fields --> queue["Очередь<br/>пишется в фоне"]
  queue --> smb[("Probe otel.xlsx<br/>сетевой диск")]
  queue --> drive[("Probe otel.xlsx<br/>Google Drive")]
```

- На главном экране до девяти бирок (сетка 3 × 3). Бирка отправляется кнопкой «Далее», когда выбрана форма (катушка или пруток) и заполнены обязательные поля.
- Каждая плавка принимается один раз (включено по умолчанию): повтор на экране, в «Загрузках» или в журнале — ошибка.
- Бирку можно добавить без фото и заполнить вручную.

## Распознавание

| Провайдер | Где работает | Примечание |
|---|---|---|
| **На устройстве** (по умолчанию) | телефон: ML Kit (Android), Apple Vision (iOS) | без интернета и ключей; поля по правилам |
| **Gemini**, **Claude**, **OpenAI** | облако провайдера | API-ключ, вводится в приложении |
| **LM Studio** | сервер в сети завода | данные не покидают сеть |

- **На устройстве.** Телефон читает строки текста; правила в `recognition/ocr/` находят поля по подписям на любом языке (Heat, Șarjă, Adag, Плавка…) и по виду значения. Подписи правятся в «Расширенные → Правила». Проверено на настоящих чтениях бирок 11 заводов (`tests/fixtures/ocr/`).
- **ИИ-модели** закрыты замком в «Основные → Распознавание». Списки моделей — из API провайдера или [models.dev](https://models.dev). LM Studio общий для всех телефонов: смена модели ждёт, пока никто не распознаёт.
- **Качество фото.** Размытие, блик, темнота и отсутствие бирки сообщаются; подсказка в одну строку на фото говорит, что сделать («Поверните фото», «Снимите бирку ближе»).
- **«Расширенные»:** промпт, правила, читаемые поля, известные поставщики (экспорт и импорт в JSON), срок копий, размер фото.

## Журнал проб

Бирки записываются в `Probe otel.xlsx` — журнал, который ведёт цех: лист на каждый год, шапка в строках 4–6, данные с 7-й. Колонки ищутся по тексту шапки, поэтому их можно переставлять.

| Колонка | Значение |
|---|---|
| Nr. Crt. | предыдущий номер + 1 |
| Cantitatea | вес, `8126Kg` |
| Data intrare | дата записи, `DD.MM.YYYY` |
| Sarja | номер плавки |
| Producator | завод |
| Bobina / Bara | диаметр в колонке формы |
| Doc. de calitate | документ качества (необязательное поле) |

- **Приложение не создаёт таблицу.** Без журнала — ошибка `tableNotFound`, пока путь не исправят; проверка — значком в конце поля пути.
- **Строгое строение** (включено по умолчанию): запись идёт только на лист со всеми колонками журнала по порядку.
- **Скрытый лист `somascan-journal`** хранит каждую записанную бирку, поэтому прерванная запись не задваивается.
- Пустой журнал для тестов: `tests/fixtures/Probe otel.xlsx`.

## Запись в журнал

«Далее» ставит бирки в очередь, которая переживает перезапуск и пишется в фоне, по одной; состояние — в «Загрузках». На телефоне очередь пишет движок вне экрана (`src/engine`): Android — WorkManager с уведомлением, iOS — фоновая задача, до iOS 26 — Live Activity.

Одна запись (`TableWriter`), одинаково для обоих хранилищ:

1. Блокировка `<таблица>.lock`; блокировка старше 5 минут снимается.
2. Журнал читается заново, строка дописывается, все прежние значения проверяются на месте.
3. Файл заменяется атомарно; прежняя версия уходит в `backups/` (по умолчанию хранится 7 дней).
4. Записанная строка читается обратно и сверяется.

Временные сбои (нет сети, таблица открыта в Excel) повторяются с растущей паузой, до раза в 15 минут; постоянные (неверный пароль, нет таблицы, не то строение) ждут изменения настроек.

**Сетевой диск** — «Настройки → Хранилище → Сетевой диск»: сервер, общая папка, путь к существующему журналу, домен, пользователь, пароль. SMB: [smbj](https://github.com/hierynomus/smbj) на Android, [AMSMB2](https://github.com/amosavian/AMSMB2) на iOS.

**Google Drive** — вход через Google, ссылка на папку и имя таблицы. Настройка Google Cloud (один раз):

1. В [Google Cloud Console](https://console.cloud.google.com/) включить **Google Drive API**; экран согласия Internal (Workspace) или External с тестовыми пользователями; доступ `https://www.googleapis.com/auth/drive`.
2. Клиент Android: пакет `com.somascan.app`, SHA-1 ключа проекта (см. [Подпись](#подпись)).
3. Клиент iOS: bundle ID `com.somascan.app`; Client ID — в `ios/App/App/Info.plist` → `GIDClientID`, перевёрнутый ID — в `CFBundleURLSchemes`.

## Разработка

```bash
npm install
npm run dev        # веб-версия, http://localhost:5173
```

| Команда | Что делает |
|---|---|
| `npm run build` | проверка типов, сборка страницы и движка |
| `npm test` | все проверки (`node:test` + `tsx`) |
| `npm run lint` | oxlint |
| `npm run cap:sync` | сборка и `cap sync` |
| `npm run cap:run:android` / `cap:run:ios` | сборка и запуск на эмуляторе или устройстве |

После изменения веб-кода — `npm run build && npx cap sync`. Локальный SMB-сервер для проверок (Samba в Docker) — в `scripts/smb-test-server/`.

## Сборка

### Android

Android SDK (Android Studio или `android-commandlinetools`), JDK 21; `compileSdk` 36, `minSdk` 24. В `android/local.properties` — `sdk.dir=…`.

```bash
npm run build && npx cap sync android && (cd android && ./gradlew assembleDebug)
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

### Подпись

Debug и release подписываются ключом проекта `android/keystore/somascan.jks`, пароли — в `android/keystore.properties`. Оба файла **не в git**: их переносят вручную и хранят резервную копию — без ключа установленное приложение не обновить. SHA-1: `AA:67:2E:F2:C4:DB:4C:CD:2A:EB:78:15:64:C5:C6:2A:FD:88:87:88`.

### iOS

macOS с Xcode 26+; минимум iOS 16.2. Зависимости — через Swift Package Manager.

```bash
npm run cap:ios          # открыть в Xcode, затем Run
```

Если не находится `simctl`: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.

## Структура

```
src/
  app/                  корневой компонент, шапка
  components/           общий UI
  features/
    recognition/        провайдеры, списки моделей, поля бирки, правила на устройстве, фото
    workspace/          главный экран: бирки, сетка, карточка результата, правка
    settings/           настройки и их вкладки
    uploads/            очередь, журнал (xlsx), сетевой диск (smb), Google Drive
  engine/               движок фоновой выгрузки
  lib/, hooks/          инфраструктура без бизнес-логики
  locales/              тексты en / ro / tj / ru
tests/                  проверки и фикстуры
android/, ios/          нативные проекты и плагины
```

Соглашения: импорты через `@/`; тексты только через `t()` и `locales/`; цвета только из `styles/tokens.css`; комментарии на русском; рискованные места отмечены `РИСК:`.

## Известные риски

| Что | Последствие |
|---|---|
| Недокументированные части ExcelJS (`excelInternals.ts`) | после обновления `exceljs` — `npm test` и сравнение настоящего журнала до и после записи |
| Защита от дублей — на скрытом листе `somascan-journal` | без листа повтор может дописать строку ещё раз |
| Год листа и дата — по часам телефона | неверная дата — не тот лист |
| Блокировки оцениваются по часам разных устройств | при расхождении больше 5 минут блокировка может сработать неверно |
| API-ключи и пароль SMB хранятся без шифрования | перед широкой раздачей — перенести в Keychain / Keystore |
